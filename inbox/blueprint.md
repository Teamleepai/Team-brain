# inbox/blueprint

- [ ] Checkpoint kit assumes a **local** machine; it silently no-ops in Claude Code web/remote containers. Two concrete gaps hit on 2026-08-06 (from aaronstraz): **(a)** Step 1 says run `gh api user --jq .login`, but `gh` is not installed in remote containers — the identity check cannot run as written, and `gh auth login` is not possible there (no interactive browser, and the session holds only the shared org token). Suggested fix: fall back to the GitHub MCP `get_me` tool for the login check, and treat "cannot verify personal handle" as a hard stop with a named escape hatch instead of an unrunnable command. **(b)** Steps 2–4 assume prior work and session history are on disk, but a remote container is cloned fresh at start — `~/.claude/projects/` holds only the current session, so "back up the last N weeks" cannot succeed there at all. Suggested fix: have the kit detect the remote/ephemeral case up front (e.g. `~/.claude/sessions/*.json` → `"entrypoint":"remote"`) and say so immediately, rather than running through a flush that finds a clean tree and reads as success.
