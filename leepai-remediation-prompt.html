Read this before anything else — two corrections

1. The source audit contained an error, and this prompt fixes it. The audit's V1-01 remediation said a client-side canonical "is accepted because it is emitted into <head> during render." That is wrong. Google stated at I/O 2018 (Tom Greenaway, subsequently confirmed by John Mueller) that it does not read canonical tags from rendered HTML. The canonical must be in the raw server response. That makes prerendering a hard prerequisite, not an optional improvement — which reorders the entire fix sequence.

2. This prompt was written without access to primary documentation or the npm registry. developers.google.com, web.dev, schema.org, rfc-editor.org and registry.npmjs.org were all blocked by network policy in the authoring environment. Every package name and every standards claim below is a candidate to verify, not a verified fact. That is precisely why rules R2 and R4 are mandatory pre-flight gates rather than polite suggestions.

Part 0

Integrity protocol

Overrides everything below. You are shipping working code against an evidenced defect list, and every change must survive adversarial review by the auditor who produced it.

R1No blind fixes

Every change traces to a FINDING ID. To change something not on the list, first produce evidence that a defect exists, tagged the way the audit tags evidence. Unrequested refactors are defects.

R2No unverified dependencies

Before installing any package, verify against the live registry that it exists, its latest version, its last publish date, and whether it is maintained. A prompt naming a package that was renamed or abandoned is worse than no prompt.

npm view <package> version time.modified deprecated repository.url

R3Measure before fixing anything [INFERRED]

The audit tagged findings [OBSERVED] (proven from fetched bytes) or [INFERRED] (reasoned, with a stated falsification test). Fix observed findings directly. For inferred findings, run the falsification test first. If it falsifies the finding, do not fix it — report that it was wrong.

R4Cite the standard, and retrieve it live

Every architectural decision cites a primary source with publisher, full URL, and date. Retrieve during execution; never answer from memory — especially on CWV thresholds, whether Google reads rendered canonicals, which structured data still produces rich results, mobile-first indexing status, and robots.txt directive support.

R5Manual action firewall — the one that gets clients penalised

You may not emit a single structured-data property a user cannot see on the rendered page. Forbidden here unless the content becomes visible first: AggregateRating and ratingValue (no star ratings exist on this site), Review (one testimonial, no rating), priceRange and Offer price (pricing says "custom plan"), openingHoursSpecification, and any sameAs you have not confirmed returns 200. If a property would help but the content is absent, the output is "add this content first" — never "add the markup anyway."

R6Myth firewall — do not "fix" non-problems

Not documented Google ranking factors; effort spent here is stolen from the real list: keyword density · LSI keywords (Google has publicly denied using LSI) · TF-IDF as a ranking lever · meta keywords · bounce rate · Domain Authority / Domain Rating / Trust Flow (third-party vendor metrics) · Lighthouse score as a direct ranking factor (the documented signal is field Core Web Vitals) · rel="next"/"prev" · word-count minimums · "Analytics data is a ranking factor".

Specifically: do not add FAQPage markup. FAQ rich results were restricted in August 2023 and subsequently withdrawn. Verify current status before writing any FAQ markup. The fix for the FAQ defect is getting answer text into the DOM.

R7Every fix ships with its verification

No fix is complete until a command proves it landed and you have pasted the actual output. "I updated the config" is not evidence. The output is the evidence.

R8Declare what you could not do

If a fix needs access you lack — DNS, Cloudflare dashboard, Search Console, registrar — do not silently skip it. Produce exact steps and values, and mark it BLOCKED — AWAITING ACCESS.

R9No fabricated outcomes

You may not predict a ranking improvement, a traffic percentage, or a timeline to page one. State fixes in mechanism terms only: "this page is currently ineligible for X; this change makes it eligible."

// functions/_middleware.js  (Cloudflare Pages Functions)
const KNOWN = new Set(['/', '/demo', '/privacy', '/terms', '/sms-terms']);

export async function onRequest(context) {
  const { request, next } = context;
  const url = new URL(request.url);

  // collapse repeated slashes -> 301 (closes V1-04)
  if (/\/{2,}/.test(url.pathname)) {
    url.pathname = url.pathname.replace(/\/{2,}/g, '/');
    return Response.redirect(url.toString(), 301);
  }

  const path = url.pathname.replace(/\/+$/, '') || '/';
  const isAsset = /\.[a-z0-9]+$/i.test(path);

  if (isAsset || KNOWN.has(path)) return next();

  const shell = await next(new Request(new URL('/', url), request));
  return new Response(shell.body, { status: 404, headers: shell.headers });
}

Part 6

The honest ceiling

This prompt cannot guarantee 100/100, and any prompt claiming it can is lying to you

Four reasons, stated plainly.

  1. The rubric is bespoke and partly subjective. The 100-point scale comes from the companion audit prompt, not from Google. Its LOW-severity findings are auditor's-judgement calls. A different auditor — or the same one on a different day — finds a different set of cosmetic issues. No external body certifies a 100.
  2. Vector 3 cannot be scored without field data you may not be able to generate. CrUX requires enough real traffic at the URL or origin level to meet its reporting threshold, over a 28-day window. A low-traffic site may never have URL-level CrUX data at all. If that is the case here, Vector 3 stays UNSCORED through no fault of the code, and the maximum honest score is 85 — exactly what the source audit reported. That is a traffic problem, not an engineering problem.
  3. Some fixes take time to be reflected, not just to ship. Canonical consolidation, index-bloat cleanup from the soft-404 fix, and re-indexing of prerendered content all depend on Google's recrawl schedule. The code can be correct on day one and the audit still find symptoms on day two.
  4. Vector 6 is scored against a query set that is currently inferred. Until FIX-15 confirms it, the content score is measured against a guess.

What this prompt can deterministically achieve

  • Every [OBSERVED] finding closed, with command output proving it
  • Every [INFERRED] finding either fixed or falsified on measured evidence
  • The CRITICAL hard cap lifted — no noindex, no Disallow: /, no off-page canonical, no JS-only primary content, HTTPS enforced
  • Vectors 1, 2, 4, 5, 7 and 8 driven to full weight — every finding in them is deterministic and verifiable
  • Vector 3 moved from UNSCORED to measured, if field data exists
  • Confidence Grade raised from C to A, by establishing Search Console and field data access — the single highest-leverage item on this list, because it removes the blindness rather than the symptoms

Report the ceiling honestly in §0 of your output. If you cannot reach 100, say what the real maximum is and why. A short honest report beats a long confident one.
